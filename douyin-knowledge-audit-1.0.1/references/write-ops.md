# 写操作纪律：三个量级，三条规矩

技术难度三级差不多（都是点击和输入），**风险差三个量级**。所以问题不是"能不能"，是"该不该由 Agent 按最后一下"。

| 动作 | 可逆性 | 后果 | 规矩 |
|---|---|---|---|
| **点赞** | 完全可逆 | 无 | 可代办。单次 ≤20，间隔 ≥3s |
| **回复评论** | 可删，但**已推给对方** | 社交关系已发生 | 先出草稿，人点头才发 |
| **发视频** | **不可逆** | 进推荐池、影响账号权重 | 只做到"停在发布按钮前" |

## 点赞：为什么能代办

因为可以**双向验证**。点一下数字减一，再点一下数字复原——两端都变，才叫真的生效。

```js
const read = () => page.evaluate(() => {
  const bar = [...document.querySelectorAll("div")]
    .filter(e => /^\d+$/.test((e.innerText || "").trim()) &&
                 e.getBoundingClientRect().width > 40)
    .slice(0, 4);
  return bar.map(e => e.innerText.trim());
});
console.log("点前", await read());
await page.mouse.click(x, y);
await page.waitForTimeout(2000);
console.log("点后", await read());   // 数字必须变，没变就是没点上
```

找不到按钮时按顺序怀疑：
1. **视口太矮**，操作栏在下沿之外 → 用 `Emulation.setDeviceMetricsOverride` 拉高。
2. 有多份同名元素，选到了隐藏的那份 → 遍历比对 `getBoundingClientRect()` 宽高。
3. 需要 hover 才显形 → 先把鼠标移进播放区。

**点完必须还原。** 测试性点赞不要留在别人作品上。

## 回复评论：为什么先出草稿

发出即达。删了也没用，对方已经看到。所以流程是：

```
读取评论 → 拟回复 → 展示草稿给人看 → 得到明确同意 → 填入 → 提交 → 回读确认
```

已实测可用的结构：评论管理页 `https://creator.douyin.com/creator-micro/interactive/comment`，回复框是 `[contenteditable="true"]`，占位文案「有爱评论，说点好听的~」，旁边有发送按钮。

**回读确认**是必须的——提交后要读一次自己发出的内容，不能只凭"我点了"就报成功。

## 发视频：为什么停住

上传页有真实的 `input[type=file]`（accept 含 mp4/mov/mkv），可以 `setInputFiles` 直接投喂。**技术上完全能走通到发布。** 但那一步之后：

- 进推荐池，影响账号权重，**撤不回来**
- 平台对上传预审有风控，无人值守批量发会掉权重
- "这条该不该发"是判断，不是操作

所以边界定在：**传好文件、拟好标题话题封面、截图确认、停在发布按钮前。最后一下人按。**

## 三条通用红线

1. **不无人值守跑写操作。** 每次公开动作都有人在环。
2. **不批量。** 点赞超过 20、评论超过 5、发布超过 1，一律先停。
3. **不代判价值。** "这条内容好不好"、"该不该发"——Agent 给建议，不给决定。

## 测能力的正确姿势

想验证写权限，**在自己账号的内容上测**，不要在别人作品上试。

- 点赞：找自己的一条视频，点一下看数字变没变，再点回来。
- 评论：在自己作品下留一条可删的测试评论。
- 发布：传一个练手文件，到发布页就撤。

测完写清三件事：哪个动作、变化前后数值、有没有还原。
