# 盘查方法：把三千条砍成七条

## 第一步：先算时间账，再谈学习

```
收藏条数 × 单条 20 分钟 = 名义学习时长
```

例：224 条去重候选 × 20 分钟 ≈ **75 小时**。三千条 ≈ **一千小时**。

**这一算，问题就换了。** 原来的问题是"怎么学完收藏夹"，真实问题是"**从收藏夹里挑出一条能立刻接上现有项目的最小路径**"。

不算这笔账，任何"学习计划"都会在第 3 天崩掉——因为它从出生起就不可执行。

## 第二步：按主题打标，同时盯住"未命中"

给每条打主题标签（工具 / 制作 / 运营 / 教学 / 商业……关键字表见 scripts/classify.py）。

关键动作是**统计未命中**：

| 类别 | 命中数 | 怎么读 |
|---|---|---|
| 命中集中在前三类，占八成 | — | 这是样本的主题分布，需核对具体类别和项目目标，不能直接推断能力结构 |
| 有明显主题一条都没有 | 0 | 这是待核验方向；可能是采样未覆盖、标题漏标或已通过其他渠道学习 |

盲区才是真交付。收藏是"想要的账"，盲区是"欠的账"。

判断盲区的三个筛子：
1. **手上项目正卡在这吗？**（卡了还 0 条 = 高危）
2. **有交付压力吗？**（要交付给客户/学员的）
3. **是"迟早踩雷"型吗？**（合规、版权、成本）

## 第三步：三条原则砍到 7 条

| 原则 | 反例 |
|---|---|
| **能接上现有项目** | "三年后 might 用得上"的一律砍 |
| **学完当天有产物** | 只有"认知提升"没有交付物的，归入"可听"不归入"要学" |
| **一条覆盖一类** | 同类 5 条只留信息密度最高的 1 条 |

砍完剩 7 条——**一周的量**。多一条都不要。留 20 条 = 一条都不会做。

## 第四步：排期要挂在产物上

不要写"周一学 A"。要写"周一学 A → 产出 B"。

| 天 | 学什么 | 当天产物 |
|---|---|---|
| D1 | 全流程演示 | 一个能跑通的最小样例 |
| D2 | 某个具体技法 | 拿自己现有作品重做一版对比 |
| D3 | 工程化/复用 | 一个进自己技能库的条目 |
| … | … | … |

**没有产物的日子必须删掉**，不要用"复习"占位。

## 第五步：验证——别替作者背书

清单里每条都要经得起"我现在点开还在吗"。

- 打开详情页核对**赞/评/藏**、发布时间。
- 视频里提到"GitHub 有仓库"时，**去找仓库本身**，找不到就写"作者提及但未定位"，不要替他说成"已开源"。
- 引用第三方仓库时核实：星数、许可证、最近提交、能不能真的下载解包。

我们真实踩过一次：作者口播说 GitHub 有仓库，视频页不暴露外链，评论区要签名接口——**结论只能是"未定位"，不是"已开源"。** 但同生态里有更硬的替代（另一仓库 4000+ 星、MIT、可实测下载），那就是更好的答案。

## 常见走偏

| 走偏 | 表现 | 修法 |
|---|---|---|
| 搬运当盘查 | 把 224 条标题原样贴出来 | 必须给判断：留哪 7 条、为什么砍 |
| 切片当全量 | "你收藏了 718 条" | 写清 718 / 实际总数 / 覆盖率 |
| 只分类不排序 | 六组清单，没有优先级 | 每组标"必学 / 可选 / 只听" |
| 忽略盲区 | 只报有的，不报没有的 | 盲区表至少三行 |
